# PRD v0.6

기준: 와이어프레임(`pages/v0.1/index.html`, 2026-10-12) + 사이트맵 기준 8화면 설명. 현재 구현과의 차이는 아래 변경 이력에 정리

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 | Safe Drive |
| 가치 제안 | 초행길도 안심하고, 사고 위험도 낮은 길로 |
| 한 문장 설명 | 출발지·도착지만 입력하면 위험 구간을 피해 알려 주는 모바일 웹 서비스 |
| 핵심 사용자 | 초행길을 운전하는 사람 |
| 대표 과업 | 출발지·도착지를 입력해 경로의 위험 구간을 확인하고, 마음에 드는 경로를 저장 |
| 데이터 | 도로교통공단 공공 사고 데이터 (구간명, 사고 건수, 위험등급, 좌표 등) |
| 저장 방식 | 로그인 없음, 모든 사용자 기록은 LocalStorage |
| 플랫폼 | 아이폰 앱 화면(폭 430px 한 열, 하단 탭 바 4개 + TOP 버튼) |

## 2. 범위

| 포함 | 제외 |
|---|---|
| 경로 입력과 모드 선택, 위험 구간 목록(필터·정렬), 구간 상세, 위험등급 안내, 즐겨찾기, 최근 검색 | 로그인·회원가입, 서버 저장, 실시간 교통 정보, 길 안내(내비게이션) |
| 결과 없음·오류·저장 없음 상태 화면 | |
| 심화 트랙: 지도 뷰(Naver Maps API), 사고 유형 요약 | |

## 3. 화면 (8개)

| # | 화면 | 목적 | 주요 데이터 |
|---|---|---|---|
| 1 | 홈 | 출발지·도착지·모드를 입력해 탐색 시작 | origin, destination, routeMode, recentSearch[], favoriteRoute[] |
| 2 | 위험 구간 목록 (결과 있음) | 경로의 위험 구간을 등급·사고 건수와 함께 확인 | segmentId, roadName, roadType, accidentCount, riskLevel |
| 3 | 위험 구간 목록 (결과 없음·오류) | 상태별 안내와 복구 행동 제공 | screenState |
| 4 | 구간 상세 | 한 구간의 사고 건수·주소·도로유형 확인, 재탐색, 즐겨찾기 | lat, lng, address, accidentTypeBreakdown, isFavorite |
| 5 | 위험등급 안내 | 등급 4종의 의미와 색상 범례 | (정적 문구) |
| 6 | 마이 · 즐겨찾기 | 저장한 경로 확인과 해제 | favoriteRoute[] |
| 7 | 마이 · 최근 검색 | 최근 검색 10건 확인과 재탐색 | recentSearch[] |
| 8 | 필터·정렬 | 등급·도로유형·정렬 조건 선택 | riskLevel[], roadType[], sortBy |

공통: 하단 탭 바(홈 · 경로 찾기 · 위험 구간 · 마이), 상단 헤더(로고 · 로그인/로그아웃), TOP 버튼. v0.5에서 **경로 찾기** 화면(`pages/route.html`)을 탭으로 추가했다. 구간 상세·위험등급 안내·필터는 탭 바를 숨기고 ←로 복귀.

## 4. 기능 요구사항

| 구분 | 기능 | 완료 조건 |
|---|---|---|
| Must | 경로 입력 | 출발지와 도착지를 모두 입력해야 탐색 버튼이 활성화된다 |
| Must | 경로 비교 | 빠른 경로와 안전 경로(시간 제한 안에서 지나는 사고 건수 합이 가장 적은 후보)를 지도와 수치로 비교한다. 더 안전한 후보가 없으면 같은 경로로 보여 주고 그 사실을 알린다 |
| Must | 모드 선택 | 기본 / 안전우선 / 4등급 제외 중 하나를 선택하면 결과에 반영된다 |
| Must | 위험 구간 목록 | 조건에 맞는 구간이 등급 배지·사고 건수와 함께 나오고, 결과 건수가 표시된다 |
| Must | 필터·정렬 | 위험등급(다중), 도로유형(다중), 사고 많은 순 정렬을 적용·초기화할 수 있다 |
| Must | 구간 상세 | 사고 건수·도로유형·주소·위험등급이 표시된다 |
| Must | 즐겨찾기 | 저장·해제가 가능하고 새로고침해도 유지된다 (이 기기의 LocalStorage, 서버로 보내지 않음) |
| Should | 회원 | 이메일 인증 후 비밀번호로 가입·로그인·비밀번호 찾기·탈퇴. 로그인하면 제보·최근 검색이 계정(서버 DB)에 저장돼 다른 기기에서도 보인다 |
| Should | 내 데이터 이동 | JSON 내려받기·파일/붙여넣기 가져오기로 즐겨찾기·제보·최근 검색을 옮긴다 |
| Must | 최근 검색 | 최대 10건을 검색 시각순으로 보관하고, 탭하면 같은 조건으로 재탐색한다 |
| Must | 상태 화면 | 로딩, 결과 없음(마지막 조건 해제), 오류(다시 시도), 저장 없음을 구분해 보여 준다 |
| Should | 위험등급 안내 | 등급별 의미와 색상(4 빨강, 3 주황, 2 노랑, 1 초록)을 설명한다 |
| 심화 | 지도 뷰 | 구간 좌표로 지도에 표시하고, API 실패 시 텍스트 정보만으로 판단할 수 있다 |
| 심화 | 사고 유형 요약 | 추돌·좌회전·보행자 등 집계를 보여 주고, 데이터가 없으면 영역을 숨긴다 |
| 심화 | 재탐색 | 현재 구간을 제외하고 경로를 다시 찾는다 |
| 심화 | 안내 정보 | 안내 화면에 남은 시간·거리·도착 시각·(GPS) 속도, 앞길 교통 막대, 단속 카메라가 가까워지면 제한속도를 보여 준다. 길찾기 응답·공공데이터에 값이 없으면 숨기고 이유를 알린다 |

## 5. 사용자 흐름

| 흐름 | 단계 |
|---|---|
| **A. 경로 탐색** (대표) | 홈 → 출발·도착·모드 입력 → 위험 구간 목록 → 구간 상세 |
| **B. 조건 조정** | 위험 구간 목록 → 필터·정렬 → 적용 → 목록 갱신 |
| **C. 재탐색** | 구간 상세 → 이 구간 피해서 재탐색 → 위험 구간 목록 |
| **D. 저장·재사용** | 구간 상세 → 즐겨찾기 저장 → 마이 → 항목 탭 → 재탐색 |
| **E. 최근 검색** | 마이 → 최근 검색 → 항목 탭 → 같은 조건으로 재탐색 |
| **예외** | 결과 없음 → 마지막 조건 해제 / 오류 → 다시 시도 (즐겨찾기·최근 검색은 유지) / 저장 없음 → 목록으로 이동 안내 |

## 6. 사이트맵

홈 · 경로 찾기 · 위험 구간 · 마이 (하단 탭 4개)

- 홈 → 경로 비교 → 예습 / 안내
- 경로 찾기 → 경로 비교 → 예습 / 안내
- 위험 구간 목록(검색 · 필터 · 정렬) → 구간 상세, 제보
- 마이(즐겨찾기 · 최근 검색 · 내 제보) → 데이터 관리, 로그인/가입

## 8. 비기능 요구사항

- 로그인 없이 모든 화면을 이동할 수 있다. 회원은 선택이며, 회원 정보(닉네임·이메일)만 서버에 저장하고 즐겨찾기·제보·검색 기록은 기기에만 둔다.
- 오류 상태에서도 즐겨찾기·최근 검색 데이터는 유지된다.
- 위험등급 색상은 모든 화면에서 같은 규칙으로 고정한다.
- 외부 API(지도)가 실패해도 텍스트 정보만으로 판단할 수 있어야 한다.
- 교통 상황·제한속도처럼 외부 데이터가 있어야 하는 정보는 값이 없으면 숨기고, 비슷해 보이는 값으로 대신 채우지 않는다.

### 9.2 톤앤매너
| 규칙 | 내용 |
|---|---|
| 화면 문구 | 해요체 (예: "불러오지 못했어요"). "~합니다"는 쓰지 않는다 |

| 용어 | 위험 구간 · 사고 다발지점 · 제보 · 즐겨찾기로 통일 |

| 아이콘 | 이모지 없음. 한 가지 선 아이콘 세트. 더보기는 화살표 |

| 색 | 메인 초록, 흰 면, 차콜 글자. 위험등급 4색은 유지 |
| 화면 기준 | 아이폰 앱 화면(393px 기준, 375~440px 검수). 데스크톱에서도 본문 폭은 430px로 제한하고 가운데 한 열로만 표시. 좌우 여백 16px, Safe Area(상단·하단) 반영, 입력창 16px(iOS 확대 방지), 가로 스크롤 없음 |
| 오류·빈 화면 | 무슨 일인지 → 어떻게 하면 되는지 → 버튼 순서 |

### 9.3 프로토타입 (사용자 흐름 확인)
v0.5는 화면을 그림으로 만든 것이 아니라 실제로 눌러서 이동하는 웹 앱이다. 아래 흐름이 끊기지 않는지 확인했다.

| # | 흐름 | 단계 | 확인 |
|---|---|---|---|
| P1 | 경로 비교 (홈) | 홈 → 출발지·도착지 입력 → 경로 비교 → 경로 즐겨찾기 → 예습 / 안내 시작 | 카카오 응답을 가짜로 대신해 확인 |
| P2 | 경로 비교 (탭) | 경로 찾기 탭 → 출발지·도착지 입력 → 경로 비교 (이후 P1과 동일) | 화면 이동·탭 활성 확인 |
| P3 | 위험 구간 | 위험 구간 탭 → 검색·필터·정렬 → 구간 상세 → 구간 즐겨찾기 | 확인 |
| P4 | 다시 열기 | 마이 → 즐겨찾기·최근 검색·내 제보 → 항목 탭 | 확인 |
| P5 | 데이터 · 계정 | 마이 → 데이터 관리 / 로그인·가입 / 로그아웃(확인 창) | 확인 |
| P6 | 제보 | 위험 구간 → 제보 → 저장 → 마이 → 내 제보 | 확인 |

실제 카카오 길찾기와 실제 지도(OpenStreetMap · Leaflet)는 데스크톱 브라우저에서 키를 넣어 경로 안내 화면(실제 도로를 따르는 경로선·회전 안내)과 위험 구간 목록 지도가 뜨는 것을 화면으로 확인했다(11/22). 안전 경로를 위한 우회(경유지) 호출이 실제 카카오에서 경로를 돌려주는지는 경로 비교 화면의 "우회 경로 N개 포함" 문구로 확인해야 하며, 아이폰 실기기와 실제 기기 음성 확인도 남아 있다.

### 12주차에 새로 한 것
| 영역 | 변경 |
|---|---|
| 로그인 방식 | 이메일 인증번호만으로 로그인하던 방식을 **이메일 + 비밀번호**로 변경. 가입·비밀번호 찾기에서만 이메일 인증번호를 사용. 비밀번호는 8~64자·영문+숫자, 흔한 비밀번호·이메일·닉네임이 들어간 것은 거절. 서버에는 **scrypt 해시**(사람마다 다른 salt)만 저장 |
| 특정인 유추 방지 | 가입·비밀번호 찾기 화면 응답이 이메일 가입 여부와 관계없이 같음, 로그인 실패 문구 하나(틀린 비밀번호/없는 이메일 구분 불가), 계정이 없어도 같은 시간만큼 계산, 로그인 시도 횟수 제한(이메일 8회·IP 30회 / 15분), 비밀번호를 바꾸면 다른 기기 로그인 해제, 탈퇴는 비밀번호 확인, 남의 제보·검색은 접근 불가(404), 마이 화면 이메일 가림(`te****@…`) |

| 안내 화면 정리 | 왼쪽 **교통 막대 삭제**(위험 구간 앞에서 위에 뜨는 안내 카드만 남김). 아래 안내 문구를 두 줄 이내로 줄임("남은 시간·도착 시각은 길찾기 때의 예상이에요… 제한속도는 단속 카메라 위치에서만 보여요"). 남은 시간 계산에는 길찾기가 준 도로별 소요 시간을 계속 사용 |
| 모션 (홈 히어로) | 홈 상단 그림이 움직임: 안전 경로가 그려지고 → 차가 사고 다발지점을 피해 도착 → 반복, 다발지점은 계속 깜빡임. 화면 등장 효과(카드가 아래에서 살짝 올라옴). 기기의 "모션 줄이기" 설정이면 멈춤. **한계:** 차 이동은 CSS `offset-path`를 써서 오래된 브라우저에서는 차 없이 경로만 그려짐 |

**0.6의 한계(확인하지 못한 것)**
- 실제 **MySQL**(시험은 SQLite)·실제 **메일 발송**(시험은 메일 자리 출력)·실제 지도 타일·실제 카카오 호출·실제 아이폰은 확인하지 못했다.

- 로그인 시도 횟수 제한(이메일 8회·IP 30회 / 15분)만 있고, 계정 잠금·2단계 인증은 없다.

### 0.5 작업 중 이 버전에 포함된 것 (안내 화면·회원 서버)
| 영역 | 변경 |
|---|---|
| 진행 방향 지도 | 안내 화면 지도를 실제 내비처럼 **차가 가는 방향이 늘 위**로 오도록 회전: 화면보다 큰 정사각형 지도를 통째로 돌리고(어느 각도에서도 모서리가 비지 않는 크기를 계산), 차는 화면 아래쪽에 고정. 350°→10° 경계는 가까운 쪽(20°)으로 회전. 전체 보기·다발지점 보기는 북쪽 위, 나침반 버튼으로 북쪽 고정 선택. 출처 표기(© OpenStreetMap)는 회전과 무관하게 화면에 고정. 한계: 타일 속 글자도 같이 돌고(남쪽으로 갈 때 글자가 거꾸로), GPS는 약 1초마다 갱신돼 지도가 뚝뚝 움직임 → 벡터 지도(MapLibre)로 바꾸면 해결 |
| 화면 꺼짐 방지 | 주행·GPS 안내 중 Wake Lock API로 화면이 꺼지지 않게 함(지원하지 않으면 조용히 넘어감, 일시정지·종료·모드 전환 때 해제) |

| 장소 자동완성 | 출발지·도착지 입력 시 카카오 로컬 검색 후보 목록(방향키·터치로 선택). 고른 장소의 좌표를 기기에 기억해 경로를 만들 때 같은 이름을 다시 검색하지 않고 그 좌표를 사용(이름이 같은 다른 장소가 잡히는 문제 방지). 키가 없으면 목록 없이 기존처럼 동작. `js/suggest.js` |
| 오프라인 지원 | 서비스 워커(`sw.js`)로 화면 파일과 사고 데이터를 기기에 저장. 같은 사이트 파일은 네트워크 우선(새 버전이 바로 보이게), 끊기면 저장본 사용. 오프라인 안내 띠 표시. 오프라인에서도 위험 구간 목록·홈·구간 상세가 열리고, 경로 만들기와 지도 타일은 연결이 필요. 파일을 추가하면 `sw.js`의 목록과 버전을 올려야 함 |
| 자동 점검 | `tests/e2e.mjs` — 실제 브라우저(Playwright)로 115개 항목 확인(경로 후보·음성·자동완성·지도·오프라인·가로 넘침·오류). 카카오 응답과 지도 라이브러리는 가짜로 대신하므로 키 없이 실행(`npm test`). 시험 중 발견해 고친 문제: 목록을 닫는 Esc가 입력창 내용을 지우던 것, 로컬 주소(127.0.0.1)에서 서비스 워커가 등록되지 않던 것. 화면 전환 효과를 넣었다가 브라우저 오류가 나서 뺌 |
| 연습 모드 음성 | 안내 화면의 가상 주행은 경로 길이와 상관없이 약 1분에 끝나서 음성("300미터 앞…")과 화면이 어긋났음. 이름을 시뮬레이션에서 **연습**으로 바꾸고, 연습에서는 음성을 내지 않으며(음성 버튼도 숨김, 안내 문구 표시) **실제 GPS 모드에서만** 음성 안내가 나오도록 변경 |
| 출처·안내 문구 | 모든 화면 하단의 문서식 출처·유의 문구(푸터)를 없애고, 마이의 "데이터 출처 · 이용 안내"로 여는 바텀 시트 한 곳에 모음(데이터 출처, 안전 경로 기준, 유의 사항, J·A·U 표시 뜻, 저장 위치). 구간 상세에는 데이터 종류에 맞는 출처 한 줄만 남김 |
